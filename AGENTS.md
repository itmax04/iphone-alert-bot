# AGENTS.md — инструкции для ИИ-агентов и разработчиков

Сначала прочитай `README.md` (функции, расписание, карта файлов, таблицы D1). Здесь — правила, которые легко нарушить.

## Контекст в одном абзаце

Cloudflare Worker (JS, ES-модули, без сборки) для закупки iPhone на перепродажу: мониторит Kleinanzeigen в
23 городах вокруг Ростока, всю землю Mecklenburg-Vorpommern раз в 3 часа и отдельно выбирает лучшие предложения
по всей Германии (медиана рынка + маржа по ценам продажи владельца в Украине). Данные — Cloudflare D1 (`DB`).
Владелец общается по-русски; тексты бота — на русском, сообщения продавцам — на немецком.

## Жёсткие ограничения платформы

1. **10 мс CPU на запуск.** Текущая нагрузка ~7–15 мс — уже на грани. Не добавляй работу в `runCity`/`runGermany`
   без замера (`npm run tail` → `cpuTime`).
   - Разбирай полностью **только новые** объявления: `fetchCity` возвращает `{id, raw}`, `parseArticle` — для новых.
   - Проверено: `HTMLRewriter` (~18 мс) и чтение тела по кускам (~21 мс) **дороже** `await r.text()` (~11 мс).
   - `RegExp` — собирать один раз на уровне модуля.
2. **Один запуск — одна страница.** Нужно больше страниц — распредели по нескольким запускам (как `mv.js`).
3. **Cron на аккаунт — 5, заняты все.** Новые задачи встраивай в `cityFor`/`HIGH_CYCLE` или в слоты `CRON_MEDIUM`.
4. **D1:** следи за числом прочитанных строк — медиану считай с кэшем на запуск (`medianCache` в `deals.js`).
5. После `deploy` новые cron начинают срабатывать через ~5–10 минут.

## Правила владельца (не менять без явной просьбы)

- **Не обходить защиту сайтов** (OLX 403, капчи, прокси, headless) — источник не подключаем.
- **Не писать продавцам автоматически** — только готовый текст (`src/messages.js`).
- **Не коммитить секреты** (токен, `RUN_KEY`, `WEBHOOK_SECRET`, Chat Id) — только `npx wrangler secret put`.
- Частота и пороги «лучших» выбраны по данным (см. README). Меняешь — объясни владельцу, сколько сообщений будет в день.
- Мониторинг городов «работает как работал» — новые функции делай отдельно, не меняя его поведение без просьбы.

## Как вносить изменения

1. Город: запись в `src/cities.js` (`slug` и `loc` берутся из URL поиска Kleinanzeigen вида
   `/s-handy-telekom/<slug>/…/k0c173<loc>`). Первый запуск нового города — молчаливый.
2. Изменения схемы: новый файл `db/migrations/00N_*.sql` **и** то же в `db/schema.sql`; применить
   `npx wrangler d1 execute iphone-alert-bot --remote --file db/migrations/00N_*.sql`.
3. Команды Telegram: `COMMANDS` в `src/commands.js` → после публикации `GET /setup?key=…`.
4. Настройки владельца (`/price`, `/sell`, `/margin`) живут в `settings` (D1) — не зашивай их в код.

## Проверка (обязательно перед тем, как сказать «готово»)

```bash
for f in src/*.js scripts/*.js; do node --check "$f"; done
npm run check                      # живые страницы локально
npm run deploy
npm run tail                       # cron-запуски: outcome ok, без exceptions, cpuTime ≈ ≤ 10–15 мс
curl "https://iphone-alert-bot.<subdomain>.workers.dev/run?key=$(cat .run_key)&city=berlin&debug=1"
```

## Частые ловушки

- Разметка Kleinanzeigen (Tailwind) меняется — опирайся на `data-adid`, `data-href`, JSON-LD.
- `modelOf` возвращает канонические имена («iPhone 15 Pro Max») — ключи `/sell`, `/price`, `prices` зависят от них.
- `seen` используют и города, и обход MV (`sent = 2`); `deal_seen` — только лента Германии. Не путай.
- `stats` содержит строки `city = 'mv'` — учитывай при суммировании по городам.
