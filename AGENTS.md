# AGENTS.md — инструкции для ИИ-агентов и разработчиков

Сначала прочитай `README.md` (функции, расписание, карта файлов, таблицы D1). Здесь — правила, которые легко нарушить.

## Контекст в одном абзаце

Cloudflare Worker (JS, ES-модули, без сборки) для закупки техники на перепродажу: 12 лент Kleinanzeigen —
3 региона (Berlin, Hamburg, вся Mecklenburg-Vorpommern) × 4 группы (телефоны, планшеты, MacBook, Apple Watch),
частные продавцы, от 150 €. Модель распознаёт каталог; цена сравнивается с медианой рынка и ценами продажи владельца
в Украине. Данные — Cloudflare D1 (`DB`). По умолчанию режим наблюдения (`/mode`): бот считает, но не присылает.
Владелец общается по-русски; тексты бота — на русском, сообщения продавцам — на немецком.

## Жёсткие ограничения платформы

1. **10 мс CPU на запуск.** Текущая нагрузка ~7–15 мс — уже на грани. Не добавляй работу в `runFeed`
   без замера (`npm run tail` → `cpuTime`).
   - Разбирай полностью **только новые** объявления: `fetchFeed` возвращает `{id, num, raw}`, `parseArticle` — для новых.
   - Проверено: `HTMLRewriter` (~18 мс) и чтение тела по кускам (~21 мс) **дороже** `await r.text()` (~11 мс).
   - `RegExp` — собирать один раз на уровне модуля.
2. **Один запуск — одна страница.** Нужно больше страниц — распредели по нескольким запускам (как дочитывание
   страниц в `feeds.js`: поле `page` в состоянии ленты).
3. **Cron на аккаунт — 5, заняты все.** Новые задачи встраивай в `feedFor` (`FAST`/`SLOW` в `src/feeds.js`).
   На запуск — не больше 50 подзапросов и 50 запросов D1: отсюда лимиты `MAX_SEND_PER_RUN`, `MAX_WATCH_PER_RUN`.
4. **D1 (5 млн прочитанных строк в сутки):** `marketMedian` читает одну строку таблицы `market` (пересчёт раз в ночь, `recomputeMarket`); не добавляй запросы по `prices` в дневной путь. Таблиц «виденных» объявлений нет и заводить их не нужно: состояние ленты — одна строка `feeds`. Новый `DELETE`/`SELECT` по времени — только с индексом. Проверка: `npx wrangler@4 d1 info iphone-alert-bot` → `rows_read_24h` (цель < 1 млн).
5. После `deploy` новые cron начинают срабатывать через ~5–10 минут.

## Правила владельца (не менять без явной просьбы)

- **Не обходить защиту сайтов** (OLX 403, капчи, прокси, headless) — источник не подключаем.
- **Не писать продавцам автоматически** — только готовый текст (`src/messages.js`).
- **Не коммитить секреты** (токен, `RUN_KEY`, `WEBHOOK_SECRET`, Chat Id) — только `npx wrangler secret put`.
- Меняешь частоту, ленты или отбор — объясни владельцу, сколько сообщений будет в день (сейчас без отбора ~575).
- **Режим отправки включает только владелец** (`/mode send`). Не меняй режим по умолчанию и `settings.mode` без просьбы.

## Как вносить изменения

1. Регион или группа: запись в `REGIONS` / `GROUPS` в `src/feeds.js` (`slug` и `loc` — из URL поиска Kleinanzeigen;
   без поискового слова адрес кончается на `c<категория><место>`, со словом — `<слово>/k0c<категория><место>`).
   Формат проверь обычным запросом (`node scripts/check.js <id>`). Первый запуск новой ленты — молчаливый.
2. Изменения схемы (последняя — `005_feeds.sql`): новый файл `db/migrations/00N_*.sql` **и** то же в `db/schema.sql`; применить
   `npx wrangler d1 execute iphone-alert-bot --remote --file db/migrations/00N_*.sql` (с разрешения владельца).
3. Команды Telegram: `COMMANDS` в `src/commands.js` → после публикации `GET /setup?key=…`.
4. Настройки владельца (`/mode`, `/price`, `/sell`, `/target`, `/haggle`, `/minprofit`) живут в `settings` (D1) — не зашивай их в код.

## Частые ловушки

- Разметка Kleinanzeigen (Tailwind) меняется — опирайся на `data-adid`, `data-href`, JSON-LD.
- Ключи модели выдаёт каталог `src/catalog.js` (`identify`); `recognize` в `filters.js` — он же, но только для включённых
  категорий (`ACTIVE_CATEGORIES`, `MIN_IPHONE`). От ключей зависят `prices`, `market`, `/sell`, `/price`: **не переименовывай
  существующие** («iPhone 13 Mini» — с большой «M», так накоплено). Сомнение в модели — `null`, а не догадка.
  Меняешь каталог — добавь реальный заголовок в `scripts/test_models.js`.
- Вариант для ключа рынка — только `recognize().variant` (существующие объёмы, LTE, SSD отдельно от RAM). Не выдёргивай
  память из текста регуляркой.
- **Новое объявление ≠ «номер больше последнего».** Лента отсортирована по времени публикации; часть объявлений выходит
  с задержкой, сверху бывают закреплённые со старым номером. Логика — `initState` / `pickNew` / `nextState` в
  `src/feeds.js`; меняешь её — добавь случай в `scripts/test_feeds.js`.
- Номер запоминается только после обработки объявления (в `done`). Пропущенные из-за лимита или сбоя Telegram должны
  остаться «новыми» — иначе они потеряются.
- В `stats` и `items` колонка `city` — это id ленты (`ph-be`); старые строки с названиями городов остались за прошлые дни.
- Таблицы `seen`, `city_state`, `deal_seen`, `deals`, `mv_seen` не используются; ночная чистка их только дочищает.
